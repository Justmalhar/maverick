## 🪟 WINDOWS FIX PASS (2026-06-23) — what shipped

Fixes committed this pass (all on `Maverick-Windows`):

- **jest-dom harness** (`vitest.config.ts`): inline `@testing-library/jest-dom`
  so `expect.extend` matchers register (node 24 + vitest 2 dup-instance). Unblocked the
  whole component suite.
- **`bun run tauri dev`** (`scripts/tauri.mjs` + package.json): wrapper prepends
  `$CARGO_HOME/bin` so tauri-cli's `cargo metadata` resolves regardless of the shell's PATH.
- **Window controls** (`capabilities/default.json` + `lib.rs`): added
  `core:window:allow-close/minimize/maximize/toggle-maximize/...` (the buttons' calls were
  rejected and swallowed by `safe()`); `set_decorations(false)` on Windows/Linux so the
  native frame and custom chrome don't both render.
- **Windows PTY exit (real bug)** (`core/src/pty/mod.rs`): the waiter joined the ConPTY reader
  before dropping the master; ConPTY never EOFs the reader until the master closes, so the
  join deadlocked and `pty:exit` never fired (exit detection dead + session leak on Windows).
  Fixed Windows-gated: drop the session (close master) before the join. Cross-platform PTY
  test helpers (`/bin/sh`→`cmd` on Windows).
- **Test robustness**: kanban + GridViewer `waitFor`/data-row waits (parallel-suite load).

Sweep result: worktree manager, sqlite path, deps PATH, keybindings (`$mod`) were already
Windows-correct. Residual (non-breaking): `⌘` glyphs in UI labels; `caffeinate` no-op on Windows.

### ⚠️ Known limitation — `cargo test` on the `maverick` GUI crate (Windows)

`cargo test -p maverick` fails to LAUNCH its test exe with `STATUS_ENTRYPOINT_NOT_FOUND`
(0xc0000139) — a load-time DLL entrypoint mismatch in the wry/webview2 static-import stack.
Persists with a minimal PATH and with `WebView2Loader.dll` staged beside the exe, so it's a
Windows-toolchain limitation for GUI-linked test binaries, NOT a product bug (the app builds,
`cargo check` passes, `tauri dev` runs). **Rust gate on Windows = `cargo check` +
`cargo test -p maverick-core` (275 pass).** The GUI crate's 26 unit tests compile (cargo
check) and run in CI; investigate the webview2 link/runtime for local Windows `cargo test`
later.
